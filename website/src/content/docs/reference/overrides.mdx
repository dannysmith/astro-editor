---
title: 'Overrides'
description: 'Reference for path and field settings'
---

Astro Editor reads your project rather than asking you about it: each collection's folder and file pattern come from its loader in `content.config.ts`, and its title, date, description and draft fields are detected in its schema. These settings are for when that isn't right. Set them in [Project Settings](/project-settings/), which shows what each one is using and where that came from. Where these settings are stored on disk is covered in [Advanced Preferences](/reference/advanced-preferences/).

Each setting lives in one place: the collection or the project. The image settings can be set for the project and overridden per collection.

## Collection settings

| Setting | When it's not set |
| --- | --- |
| **Folder** | Read from the collection's `glob()` loader. If Astro Editor can't read the loader, `<content folder>/<collection name>` |
| **Show files Astro skips** | Off: files the loader's pattern leaves out, like drafts named `_draft.md`, aren't shown. On, they're shown dimmed |
| **Type** (new files) | The global preference. If the collection's pattern only includes `.md` or only `.mdx` files, new files always use that type |
| **Name** (new files) | `{YYYY-MM-DD}`: new files are named with today's date. `{title}` is the title as a slug; other placeholders are dates, like `{YYYY}` |
| **Sort** | Published date, newest first, with undated files at the top |
| **Title** | A text field named `title` |
| **Description** | A text field named `description` |
| **Published date** | The first date field in the schema named `pubDate`, `date` or `publishedDate` |
| **Draft** | A true/false field named `draft`. Without one, there's no draft badge or filter |
| **Image folder** | The project's |
| **Image paths** | The project's |
| **Link URLs** | Unset: links the [Content Finder](/editor/links/#internal-links) inserts use a relative file path. Use `{slug}`, filled from a file's `slug` frontmatter or its id, as in `/writing/{slug}` |

When a collection has no schema, Astro Editor uses the field names above and reads them from each file's frontmatter.

## Project settings

| Setting | Default | Controls |
| --- | --- | --- |
| **Content folder** | `src/content` | Where collections are looked for when the content config doesn't say where they are, and whose folders become collections when there's no readable content config |
| **MDX components folders** | `src/components/mdx` | The folders the [component builder](/editor/mdx-components/) offers components from |
| **Image folder** | `src/assets` | Where dragged or inserted images are copied, in a folder named after the collection. Collections can override it |
| **Image paths** | Relative to the file | Relative to the current file (`../../assets/image.png`), or from the project root (`/src/assets/image.png`). Collections can override it |
| **Add imports** (MDX components) | Off | Whether the [component builder](/editor/mdx-components/#adding-imports) adds the import a component needs. Experimental |

The image path setting applies to image frontmatter fields and images dropped into the editor. See [Images & Files](/editor/images-and-files/).

Many Astro sites contain components which are specifically designed for use in MDX content files. Here's a simple example.

```astro title="Highlight.astro"
<span class="highlight"><slot /></span>

<style>
  .highlight {
    background: var(--color-highlight-bg);
    padding: 0 8px 4px;
  }
</style>
```

Which we might use like this.

```mdx title="my-post.mdx"
This is some <Highlight>text I wanna highlight</Highlight>.
```

We can probably remember how to use a simple component like this, but using more complex components which accept multiple props can often mean opening a code editor and looking at the component file before we can use it.

## The MDX Component Builder

Astro Editor helps with using these kinds of components by providing an interface for searching and inserting them into MDX content files. When editing an MDX file, <Kbd mac="Cmd+/" windows="Ctrl+/" /> will open a palette showing all the components inside your configured *MDX directory*. You filter the results by typing, as you'd expect.

![The MDX component builder palette listing the available components, each with a framework badge](../../../assets/mdx-builder-1.png)

Each entry shows its framework as a coloured badge and a count of its props. If the component has a doc comment above it, a short description is pulled from it and shown under the name (and is searchable too).

Hitting <Kbd mac="Enter" windows="Enter" /> will open a form with a field for each of the component's props, and a preview of what will be inserted.

![The component builder's form for a Callout component, with a field for each prop and a preview of the code to be inserted](../../../assets/mdx-builder-2.png)

Each field matches what the prop accepts: a dropdown when it only takes a few set values (a searchable one when there are lots), a switch for true/false (or a choice of *Default*, *True* or *False* when the prop is optional), a date picker for dates, a number field for numbers and a text box for everything else. Lists of values get a field you can add several to. If a prop has a default, it's shown beside its name, and any doc comment is shown under the field.

Props that take an imported image or a collection entry take the name of the variable instead, so you'll need to add the import (or load the entry) yourself.

Optional props are only inserted if you give them a value, and Astro Editor writes each one in the right MDX syntax (`count={3}`, `date={new Date('2026-01-15')}` and so on). <Kbd mac="Cmd+Enter" windows="Ctrl+Enter" /> inserts the component with your cursor in the first required prop you left empty, or in its slot. Components that wrap content go in on lines of their own when you insert them on an empty line, so you can write markdown inside them. You can use <Kbd mac="Tab" windows="Tab" /> to move between them, and <Kbd mac="Esc" windows="Esc" /> takes you back to the list of components.

![The Callout form filled in, with the preview showing each value written into the tag](../../../assets/mdx-builder-3.png)

For components written in a framework (React, Vue, or Svelte), the configure step also lets you pick a [client directive](https://docs.astro.build/en/reference/directives-reference/#client-directives) — `client:load`, `client:idle`, `client:visible`, `client:media`, or `client:only`. This controls when (and whether) Astro hydrates the component in the browser, and gets added to the inserted tag. `client:idle` is recommended for most cases. Astro components don't need one, so the option only appears for framework components.

<Aside type="caution">
While Astro Editor will insert the component itself, it **won't add an import below the frontmatter**. While this is definitely coder-mode stuff, it's not great when in writer mode because, if you're running a dev server to preview as you write, the page will break until you switch to a code editor and add the missing import.

We may add this in a future release, but in the meantime, consider adding [Astro Auto Import](https://github.com/delucis/astro-auto-import) to your site and having it import all the components in your `mdx/` directory.
</Aside>

## Starlight's Components

If your site uses [Starlight](https://starlight.astro.build/), the builder also lists Starlight's [built-in components](https://starlight.astro.build/components/using-components/), like `Aside`, `Tabs`, `Card` and `Steps`. Components that wrap other content come with it filled in: inserting `Tabs` gives you two `TabItem`s ready to label, and `Steps` gives you a numbered list.

![The component builder in a Starlight site, listing Starlight's components with a short description of each](../../../assets/mdx-builder-starlight.png)

As with your own components, you'll need to import them (`import { Tabs, TabItem } from '@astrojs/starlight/components'`) or set up auto-importing.

## What are "MDX" Components?

Any component meant to be used as above. By default, Astro Editor looks in `src/components/mdx/` and its subdirectories, but you can configure this in the [preferences](/preferences/#path-overrides). The component builder automatically detects which props and slots are available by reading the component's source code and works with well-formed components written in:

- **Astro** (`.astro` files)
- **React** (`.tsx`, `.jsx` files)
- **Vue** (`.vue` files)
- **Svelte** (`.svelte` files)
